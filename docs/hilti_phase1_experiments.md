## 1. 阶段 0 结论（本阶段的出发点）

### 1.1 差距拆解（单位 mm；视觉贡献 = LIVO − LIO-only，正数表示变差；多次重复取均值）

| 序列 | SPHERE − Omni（LIVO） | LIO-only 差 | SPHERE 视觉贡献 | Omni 视觉贡献 | 差距主要来源 |
|---|---:|---:|---:|---:|---|
| exp07 | +20.8 | +21.8 | −0.5 | +0.5 | LIO |
| exp21 | +27.8 | +33.0 | −3.5 | +1.7 | LIO |
| exp09 | +47.5 | −10.7 | +41.7 | −16.5 | 视觉 |
| exp10 | +33.4 | +5.9 | +44.1 | +16.6 | 视觉 |
| exp15 | +30.8 | −5.0 | −19.2 | −55.0 | 视觉 |
| exp16（稠密 ATE） | +8.8 | −18.0 | +23.4 | −3.4 | 视觉 |

### 1.2 其他关键事实

- SPHERE 在 0.5× 下 LIO-only 与 LIVO 的重复运行结果完全相同（标准差 0）；Omni 的 LIVO 不确定（exp09 标准差 25 mm，exp16 为 10 mm），Omni 的 LIO-only 是确定的。
- exp16：SPHERE 加视觉后 1 s RPE 变好（32.0 → 28.9 mm，与 Omni 改善幅度相当），稠密 ATE 却变差（+23 mm）。说明短时跟踪变准，但存在随时间累积的低频偏差。
- 视觉害处最大的是 exp09、exp10（穹顶，曲面多，时长最长：446 s、370 s）。

### 1.3 待验证的假设

| 编号 | 假设 | 支持它的现象 | 本阶段验证实验 |
|---|---|---|---|
| H0 | LIO-only 差异来自两边 Hilti 配置不同，而非代码 | XT32 预处理代码一致；Omni 的地图坐标变换在无回环时为恒等；仓库自带配置的 `filter_size_surf`、`gyr_cov`、`acc_cov`、`voxel_size`、`blind` 不同 | E1 |
| H1 | 视觉信息被高估：补丁内像素残差强相关，却按独立观测累加，后验协方差过小，LiDAR 后续修正被压制，偏差无法纠回 | RPE 变好但 ATE 变差；固定 `img_point_cov` 1000，8×8 补丁 × 约 180 个 | E2、E4 |
| H2 | 曲面违反球面补丁的局部平面假设，产生系统性几何偏差 | 害处集中在穹顶 exp09/exp10 | E2b、E6 |
| H3 | 参考外观过期（外观只在插入时记录一次） | 长序列、回访多 | E3 |

## 3. 实验

### E1：交换 LIO 配置（验证 H0）

**目的**：确认 exp07、exp21 的差距是否只是配置差异。

1. 先对比阶段 0 中两边实际使用的 `config.yaml`，列出 `preprocess`、`imu`、`lio`、`local_map`、`extrin_calib` 下**全部**取值不同的键，形成表格放进汇报。注意 `blind` 的语义不同：SPHERE 比较的是"距离平方 ≥ `blind_sqr`"（`src/preprocess.cpp`，`blind_sqr = blind²`），Omni 的 XT32 处理直接比较"距离平方 > `blind`"。对齐时要换算到同一物理半径。
2. 跑以下 LIO-only（`common/img_en: 0`），6 条序列（exp07、exp09、exp10、exp15、exp16、exp21）：

| ID | 程序 | LIO / IMU / 预处理参数 |
|---|---|---|
| E1-S/O | SPHERE | Omni 的参数 |
| E1-O/S | Omni | SPHERE 的参数 |

3. 判读：
   - 若 E1-S/O ≈ 阶段 0 的 Omni LIO-only，且 E1-O/S ≈ 阶段 0 的 SPHERE LIO-only（差 < 3 mm）→ H0 成立，差异来自配置。
   - 若交换后差异仍在 → 存在代码层面的 LIO 差异，逐个参数二分定位，或报告给我继续查代码。
4. **确定统一 LIO 配置 U**：从两套参数中选一套，选择标准是两个程序在 6 条序列上 LIO-only 等权均值之和最小，选定后冻结，后续所有实验（含 Omni）都使用 U。不得对单个参数做进一步搜索。

### E2：视觉噪声扫描（验证 H1）

只改 `vio/img_point_cov`，使用统一 LIO 配置 U，SPHERE LIVO，其他参数保持阶段 0 的 SPHERE 预设不变。

| ID | `img_point_cov` |
|---|---:|
| E2-1000 | 1000（对照，相当于在配置 U 下重跑基线） |
| E2-3000 | 3000 |
| E2-10000 | 10000 |
| E2-30000 | 30000 |

序列：exp09、exp10、exp16（视觉有害）和 exp15（视觉有益，用来确认改动不会把有益的情况也破坏）。

判读：
- 若 exp09、exp10、exp16 的视觉贡献随 `img_point_cov` 增大而单调减小，且 exp16 的 ATE 改善时 RPE 没有明显变差 → H1 成立。
- 若 30000 时视觉贡献趋近 0 但始终不为负 → 视觉在这些序列上只能"不添乱"，说明问题不仅仅在权重。

### E2b：补丁尺寸（区分 H1 与 H2）

Hilti 预设当前 `vio/patch_size: 8`（请先在运行配置中确认）。在 E2 中效果最好的 `img_point_cov` 下，再跑 `patch_size: 4`，序列同 E2。

- 4×4 补丁像素数是 8×8 的 1/4，覆盖的物理面积也只有 1/4。
- 若 `patch_size: 4` 在 exp09、exp10 上的改善明显大于 exp16 → 曲面（H2）影响更大，因为小补丁受曲率影响更小。
- 若各序列改善幅度相近 → 主要是信息量（H1）问题。

### E3：timing CSV 统计（验证 H3）

即阶段 0 任务书 3.2 节尚未汇报的部分。对阶段 0 的 SPHERE LIVO 运行和 E2 中最好的配置，都要输出：

1. `guard_status` 各取值占比；
2. `accepted_patches`、`selected_patches`、`cameras` 的 P10/P50/P90；
3. 按 30 s 时间窗统计 `committed` 占比和 `accepted_patches` 中位数，画随时间曲线（每条序列一张图）；
4. `vio_ms` 的 P50/P95/max；
5. `lidar_weak_ratio` 的分布。

判读：若 exp09、exp10 的 committed 率或被接受补丁数随时间明显下降（后 1/3 时段比前 1/3 低 30% 以上），支持 H3；若平稳，H3 优先级下调。

### E4：误差与视觉修正随时间的变化（定位偏差何时、朝哪个方向出现）

1. **exp16（有稠密真值）**：对 SPHERE LIO-only、SPHERE LIVO、Omni LIO-only、Omni LIVO（第 1 次重复）四条轨迹，用整条轨迹的 SE(3) 对齐，画逐时刻平移误差曲线；再把误差分解为水平（xy）和高度（z）分量，并画航向角（yaw）误差曲线。标出 SPHERE LIVO 相对 LIO-only 开始变差的时间段。
2. **全部 6 条序列（不需要真值）**：画 SPHERE LIVO 与 SPHERE LIO-only 两条轨迹的逐时刻位置差，看偏离是逐渐累积还是突然跳变。
3. **每帧视觉修正量**：`mat_pre.txt` 和 `mat_out.txt` 每行是 `时间 欧拉角(3, 度) 位置(3) 速度(3) bias_g(3) bias_a(3) 曝光 [点数]`。先阅读 `src/LIVMapper.cpp` 中 `handleVIO()` 和 `handleLIO()` 的写入位置，确认如何区分 VIO 帧的"更新前"与"更新后"两行。然后对每个 VIO 帧计算位置修正 δp（3 维）和姿态修正 δθ（3 维），输出：
   - δp、δθ 各分量随时间的曲线和累积和；
   - 各分量均值与标准差，以及均值除以标准误的比值（判断是否存在固定方向的系统性推动）；
   - LIVO 与 LIO-only 的 `bias_g`、`bias_a` 随时间曲线对比。
4. 把第 1、2 步找到的变差时间段与 E3 的 CSV 曲线对齐，看那段时间 committed 率、补丁数、`lidar_weak_ratio` 有没有异常。

判读：若 δp 或 δθ 某分量的累积和单调增长（系统性推动），支持 H1 或 H2；若 bias 在 LIVO 中明显偏离 LIO-only，说明视觉把误差吸收进了 bias 状态。

### E5：Omni 补足重复

在统一 LIO 配置 U 下，Omni LIVO 在全部 6 条序列上各跑 3 次，Omni LIO-only 各跑 1 次。exp10、exp15、exp21 目前只有 1 次，结论不可靠。

### E6（可选，需要少量日志代码）：球面补丁的平面拟合质量

只加日志，不改估计逻辑，并默认关闭（开关 `innovations/spherical_plane_quality_log`，默认 false）。

在 `src/vio.cpp` 的 `insertSphericalMapPoints` 里，补丁插入成功时，把以下信息写入新的 `<seq_name>_patch_planes.csv`：插入时间、`map_key`、补丁中心坐标、法向、所用 LiDAR 平面的半径（`visual_radius_`）、平面协方差的最小特征值或平面拟合残差（取 `PointToPlane` 或体素平面中能拿到的量）。

用 exp09、exp10 与 exp15、exp16 对比上述平面质量指标的分布。若穹顶序列的补丁平面质量明显更差，且 E2b 也指向 H2，则下一阶段在几何支撑中加入平面质量门限。
