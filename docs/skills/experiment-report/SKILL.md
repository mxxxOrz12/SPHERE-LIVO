# SPHERE-LIVO 实验报告写作规范

读者是项目负责人：懂 SLAM，但**没有参与运行**，也不会去翻你的日志。
报告要让他在 3 分钟内回答四个问题：

1. 这轮改了什么、测了什么？
2. 哪个更好、哪个更差，差多少？
3. 这个结论有多可靠？
4. 下一步做什么？

做不到这四点的报告，不论数据多全，都算没写好。

---

## 一、文件结构

每批实验输出两个文件：

- `report_zh.md`：**正文**，控制在 2 页以内（约 1500 字 + 3 张以内的表）。
- `appendix_zh.md`：**附录**，逐次运行表、配置差异、文件路径、哈希、崩溃栈、中断记录等全部放这里，篇幅不限。

正文固定为以下六节，标题照抄：

```markdown
# <实验名称>：结果报告

## 结论
## 主要结果
## 逐项判断
## 异常与失败
## 下一步
## 附录说明
```

### 1. 结论（3–6 句）
- 第一句直接回答"这轮实验说明了什么"，不要写"本报告依据……"之类的开场。
- 每句一个判断，带数字和可靠程度，例如：
  > V2 在 8 条稀疏序列上的平均误差比 Omni 低 6.1 mm（约 8%），4 个种子中 3 个方向一致，可以认为略好。
- 若本轮有阻断性问题（回归没通过、发散），放在第一句。

### 2. 主要结果（1–2 张表）
- 每张表上方写一句话说明"这张表要看什么"。
- 表格不超过 8 列；每格写 `均值 ± 标准差`，单位在表头写一次。
- 只在按第四节规则判定为"确实更好"时加粗。
- 逐次运行的明细不放这里，放附录。

### 3. 逐项判断
按任务书里的假设或问题逐条写，每条固定格式：

```markdown
**H1 视觉信息被高估**：不支持。
依据：噪声从 1000 加到 30000，exp09 的误差先升后降（200 → 238 → 221 → 157 mm），不是单调变化。
可靠程度：每个配置只有 1 次运行，差异在 Omni 自身重复波动（20–60 mm）以内。
```

结论只用四个词之一：**支持 / 不支持 / 部分支持 / 无法判断**。

### 4. 异常与失败
- 只写**影响结论判断**的异常：发散、覆盖检查失败、回归不一致、数据缺失。
- 每条写：发生在哪（序列、配置、种子）、现象（数字）、对结论的影响、是否已排除。
- 进程号、core dump、恢复过程、目录名等写进附录，正文最多一句"详见附录 B"。

### 5. 下一步
2–4 条，按优先级排序，每条说明"做什么"和"为了回答什么问题"。

### 6. 附录说明
列出附录各节和关键文件位置，一行一项。

## 二、语言规则

1. **全部用中文完整句子**。英文只保留专有名词（ATE、RPE、LIO、Omni-LIVO）和代码参数名。参数名用反引号包起来。
2. **不要把 JSON、日志原文、英文状态码放进正文**。需要时翻译成中文：

   | 原文 | 正文写法 |
   |---|---|
   | `coverage_failed` | 覆盖检查未通过 |
   | `committed` | 视觉更新被接受 |
   | `final_cost_rejected` | 更新后代价未下降，已回滚 |
   | `chi2_rejected` | 修正幅度不合理，已回滚 |
   | `initial_support_rejected` | 可用补丁不足，未做视觉更新 |
   | `exact_trajectory: false` | 轨迹与旧版本不一致 |

3. **比较一律写成"谁比谁好/差多少"**：
   - 好："V2 比 Omni 低 12.3 mm（约 11%）。"
   - 差："V2: 98.1, Omni: 110.4。"（让读者自己减）
4. **数字统一**：误差用 mm，保留 1 位小数；百分比取整；时间用 s 或 ms。同一张表精度一致。
5. **每个结论只写一次保留意见**，写在"可靠程度"里。不要每句都加"不能据此认定""仅作描述"。
6. **术语第一次出现时用括号解释一次**，之后直接用。例如："LIO-only（只用 LiDAR 和 IMU，关闭相机）"。
7. **不写过程流水账**。"首先……随后……最终……"这类叙述删掉，只写结果和判断。
8. 不用"显著"，除非做了统计检验；用"明显""略""在波动范围内"。

## 三、本项目的固定口径

| 名称 | 含义 |
|---|---|
| 稠密 ATE | exp04/05/06/16 的 IMU 六自由度真值上的绝对轨迹误差，SE(3) 对齐，不拟合尺度 |
| 1 s RPE | 1 秒间隔的平移相对误差，反映局部漂移 |
| 稀疏 RMSE | 稀疏测量点上的位置均方根误差；点数少（5–16 个），波动大 |
| LIO-only / LIVO | 关闭 / 打开相机 |
| 视觉贡献 | LIVO 误差 − 同程序 LIO-only 误差；负数表示视觉有帮助 |
| 相位 / 种子 | 每 4 组同步图像取第几组（0–3）；同一相位下两方法图像相同，可配对比较 |
| 覆盖检查 | 首位姿延迟 < 2 s，最大位姿间隔 < 0.25 s，位姿数 ≥ 预期的 95% |

分组均值：先对每条序列取各种子的均值，再对序列等权平均。稠密和稀疏两类指标**分开**统计，不混在一起。

---

## 四、判定规则

- **更好 / 更差**：同一序列上按相位配对，至少 3/4 个相位方向一致，且均值差大于相位间标准差。
- **相当**：方向不一致，或均值差小于相位间标准差。
- **无法判断**：只有 1 次运行，或数据缺失。
- 单次运行的毫米级差异不下结论。
- 覆盖检查未通过的运行不计入均值，单独在"异常与失败"里报告，并在表格对应位置标注"失败"。

## 五、改写示例

**不好的写法**（摘自以往报告）：

> E2：四序列等权平均误差选择 img_point_cov=10000，由 147.436 mm 降至 123.772 mm（降低 16.1%）。这是全局选择，不代表每条序列都改善。
> 保留限制：默认 angular_scale=1 的新旧二进制回归未通过；E2-10000 的 exp21 补充测试覆盖不合格，均不计作验证通过。

问题：参数名当主语、三位小数、限制条件堆在一起、没说"所以呢"。

**好的写法**：

> 把视觉观测噪声 `img_point_cov` 从 1000 调到 10000 后，四条序列平均误差从 147.4 mm 降到 123.8 mm（约 16%）。但改善不稳定：exp10、exp15 明显变好，exp09 反而变差 21 mm，而且这个配置在 exp21 上发散了（误差 7.2 m）。因此**暂不采用 10000**，需要用多个种子重新确认。
>
> 另外，新编译的程序在 exp04 上没有通过回归检查（和旧程序轨迹不一致），原因还没查清，详见"异常与失败"。
